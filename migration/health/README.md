# Unity Health migration

The former standalone `Backup/Unity_Health` checkout was retired on 2026-11-24.
Its GTK pages, storage, sync, widgets, dialogs, icons, tests and Android Health
Connect application are maintained in Unity WellBeing. The original MIT license
is unchanged. Android retains its package, Binder protocol, certificate pins and
signing key so existing installations and Unity connections remain compatible.

`source.tar.gz` preserves the complete original source, documentation and Unity
integration patch, including its original platform files, for historical review.
Its old installer and integration patch are historical: current installation
uses `install.py` and current Android builds use `build-android.sh` at the
WellBeing root. The existing platform bridges already contain the integration.

Local material was preserved separately from distributable source:

- `.local-data/health.db`: a consistent SQLite backup, verified against every
  original table. It includes records, settings, goals and sync identities.
- `android/.signing/debug.keystore`: the unchanged original Android key.
- `.tools/`: the original Gradle cache, verification logs and local build backups.
- `dist/legacy-health/`: all previous APKs, wheels and checksums.
- Original Unity Health UI captures were preserved at migration and remain in
  repository history; the outdated images are not part of the current showcase.

The private database, signing material, tools and distributions are ignored by
Git and excluded from Python packages. Generated bytecode, egg metadata and old
Android/Python build intermediates were discarded; they are reproducible.

WellBeing imports the migrated local database on first launch when no destination
database exists. Installation performs the same one-time import before copying
the application. Existing WellBeing databases are never overwritten. Other users'
installed Unity Health databases remain supported through `UNITY_HEALTH_DATA_DIR`
or the legacy XDG data location.
